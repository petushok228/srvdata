Тема 4. Указатели в C#.
    Назад

Указатель — это не что иное, как переменная, которая хранит адрес в памяти другой переменной. В C# указатели можно использовать только для типов значений и массивов. Поскольку структура является значимым типом, с ней можно использовать указатели, но есть одно предостережение: структура не должна содержать никаких ссылочных типов, если вы планируете использовать указатели. Указателем может быть любой из следующего:

    • Sbyte
    • byte
    • short
    • ushort
    • int
    • uint
    • long
    • ulong
    • char
    • float
    • double
    • decimal
    • bool

Небезопасное ключевое слово

Обычно, когда мы пишем код на C#, по умолчанию это так называемый безопасный код. Небезопасный код позволяет вам манипулировать памятью напрямую, в обычном мире C# и .NET Framework это рассматривается как потенциально опасное, и поэтому вы должны пометить свой код как небезопасный. Используя небезопасный код, вы теряете сборку мусора, и при прямом доступе к памяти у вас есть возможность получить доступ к памяти, которую вы не хотели, и вызвать невыразимые проблемы с вашим приложением. Небезопасный код можно использовать только в полностью доверенной сборке.

Теперь пришло время написать программный код, демонстрирующий использование указателей. Рассмотрим следующий код.

static void Main(string[] args)
{
    int age = 32;
    Console.WriteLine("age = {0}", age);
}

Очень простой кусок кода, который выведет на консоли age = 32. Теперь давайте введем указатель. Когда мы объявляем указатель, мы должны объявить его определенным образом, это переменная типа*; Звездочка (символ разыменования) информирует компилятор о том, что мы объявляем переменную-указатель, тип говорит, что мы намерены использовать указатель для хранения адреса типа type. Итак, используя наш простой фрагмент кода, приведенный выше, давайте создадим целочисленный указатель, указывающий на возраст.

static void Main(string[] args)
{
    unsafe
    {
        int age = 32;
        int* age_ptr;
        Console.WriteLine("age = {0}", age);
    }
}

Обратите внимание на использование ключевого слова unsafe, если бы мы не поместили наш код в unsafe, мы бы получили следующую ошибку компиляции.

Указатели и буферы фиксированного размера могут использоваться только в небезопасном контексте.

Мы могли бы объявить весь метод небезопасным, и это сработало бы нормально, например:

unsafe static void Main(string[] args)

Итак, что мы можем сделать с нашим указателем? Как было сказано в начале статьи, указатели содержат адреса в памяти к другим переменным, поэтому нам нужно сделать так, чтобы age_ptr указывали на местоположение памяти возраста. Для этого мы используем следующую строку кода:

age_ptr = &age;

Амперсанд «&» является референсом и означает «местоположение». Итак, если мы теперь сделаем следующее в нашем коде:

static void Main(string[] args)
{
    unsafe
    {
        int age = 32;
        int* age_ptr;
        age_ptr = &age
        Console.WriteLine("age = {0}", age);
        Console.WriteLine("age_ptr = {0}", *age_ptr);
    }
}

Теперь мы должны увидеть следующий вывод на консоли:

Возраст = 32
age_ptr = 32

По сути, с помощью строки отображения для age_ptr мы печатаем значение, хранящееся в ячейке памяти, на которую указывает age_ptr (в данном случае переменная age).

Теперь, что произойдет, если мы добавим к примеру следующее?

*age_ptr += 3;
Console.WriteLine("age now = {0}", age);

Как вы думаете, каким будет вывод (обратите внимание, что мы печатаем значение возраста)? Если вы сказали 35, вы правы! Значение возраста изменено на 35 лет. Давайте разберем строку *age_ptr += 3 и посмотрим, что происходит.

age_ptr было объявлено как целое число, то термин *age_ptr можно прочитать как «целочисленное значение в ячейке памяти, на которую age_ptr указывает». Затем мы просто прибавляем 3 к целочисленному значению, получая результат 35. Поскольку age_ptr указывает на место в памяти, где age хранит свое значение, по сути, мы изменили переменную age.

Указатели на структуры

Как упоминалось ранее, вы можете определить указатель на структуру, но вам нужно убедиться, что в структуре нет ссылочных типов, например, рассмотрим пример кода ниже:

class TestClass
{
    . . .
}

struct TestStruct
{
    public int age;
    public TestClass test;
}

В этом случае вы не сможете выполнять следующие действия:

TStruct test_struct;
TStruct* struct_ptr;
struct_ptr = &test_struct;

При компиляции этого кода вы получите сообщение об ошибке:

Не может принять адрес, получить размер или объявить указатель на управляемый тип.

Итак, давайте создадим корректную структуру и посмотрим, как мы используем указатель на структуру. Наша структура будет простой, содержащей два целых числа X и Y для симуляции координат на экране.

struct Location
{
    public int X;
    public int Y;
}

Теперь мы можем создать следующий код:

unsafe static void Main(string[] args)
{
    Location loc;
    loc.X = 100;
    loc.Y = 100;

    Location* loc_ptr;
    loc_ptr = &loc;
}

В приведенном выше коде не должно быть никаких сюрпризов. loc_ptr относится к типу Location, который является нашей структурой. Итак, как мы используем наш указатель? Чтобы получить доступ к элементам X и Y нашей структуры с помощью нашего указателя, мы можем использовать следующий синтаксис

(*loc_ptr).X;  or  loc_ptr->X;

Я знаю, какой из них я бы предпочел использовать (второй вариант), но оба выполняют точно такую же функцию. Таким образом, если мы хотим отобразить и изменить X, мы можем сделать это следующим образом:

unsafe static void Main(string[] args)
{
    Location loc;
    loc.X = 100;
    loc.Y = 100;
    Location* loc_ptr;
    loc_ptr = &loc;
    Console.WriteLine("X = {0}", loc_ptr->X);
    loc_ptr->X = 200;
    Console.WriteLine("X = {0}", loc_ptr->X);
}

Указатели и классы

Класс является ссылочным типом, поэтому вы не можете определить указатель на класс, но вы можете определить указатель на член класса, который является значимым типом. Прежде чем мы рассмотрим пример того, как это сделать, необходимо кое-что понять, прежде чем создавать указатели на члены типа значений класса.

При использовании безопасного кода сборщик мусора может перемещать объект в памяти в течение его жизни, это делается для управления свободными ресурсами и остановки фрагментации. Если у вас есть указатель на тип значения в классе, это может привести к неожиданным результатам и головной боли! Излишне говорить, что есть способ обойти эту проблему. Мы можем указать сборщику мусора не перемещать определенные объекты. Мы делаем это с помощью ключевого слова fixed. Давайте рассмотрим на примере.

Дизайн следующего класса не идеален, и любой гуру ОО-дизайна, вероятно, покачает головой над ним, но это было сделано в качестве очень простого примера.

Например

class PTest
{
    public PTest()
    {
    }
    public int age;
    public void DisplayAge()
    {
        Console.WriteLine("age = {0}", age);
    }
}
C#

И несколько примеров кода для создания экземпляра класса и последующего манипулирования открытой переменной age с помощью указателя.

unsafe static void Main(string[] args)
{
    PTest p = new PTest();

    p.age = 32;
    p.DisplayAge();

    fixed (int* age = &p.age)
    {
        *age += 3;
    }

    p.DisplayAge();
}

Обратите внимание на использование ключевого слова fixed. По сути, это гарантирует, что во время выполнения кода в фиксированном операторе объект p не будет перемещен, тем самым решая проблему нашего указателя, указывающего на неверное место в памяти, эта операция называется «закреплением».

Компиляция небезопасного кода

Для того, чтобы скомпилировать программный код, который содержит небезопасный код, необходимо сообщить об этом компилятору. При использовании компилятора командной строки необходимо выдать ключ /unsafe. При использовании Visual Studio необходимо установить флажок в свойствах проекта под названием Разрешить небезопасный код (его можно найти в разделе Сборка).

Заключение

Использование указателей в C# почти никогда не требуется, и обычно они используются только в сочетании с P/Invoke. Если у вас есть потребность в использовании указателей, вам нужно быть очень осторожным, так как вы напрямую манипулируете памятью.

Мой совет таков: не ищите причину для их использования, если вы можете выполнить свою задачу, используя безопасный код, сделайте это.
