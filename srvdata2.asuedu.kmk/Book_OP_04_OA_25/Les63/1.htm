Метод, на который ссылается делегат, нередко используется только для этой цели. Иными словами, единственным основанием для существования метода служит то обстоятельство, что он может быть вызван посредством делегата, но сам он не вызывается вообще. В подобных случаях можно воспользоваться анонимной функцией, чтобы не создавать отдельный метод. Анонимная функция, по существу, представляет собой безымянный кодовый блок, передаваемый конструктору делегата. Преимущество анонимной функции состоит, в частности, в ее простоте. Благодаря ей отпадает необходимость объявлять отдельный метод, единственное назначение которого состоит в том, что он передается делегату.

Начиная с версии 3.0, в C# предусмотрены две разновидности анонимных функций - анонимные методы и лямбда-выражения:

Анонимные функции C#

Анонимные методы были внедрены в C# еще в версии 2.0, а лямбда-выражения — в версии 3.0. В целом лямбда-выражение совершенствует принцип действия анонимного метода и в настоящее время считается более предпочтительным для создания анонимной функции. Но анонимные методы широко применяются в существующем коде C# и поэтому по-прежнему являются важной составной частью C#. А поскольку анонимные методы предшествовали появлению лямбда-выражений, то ясное представление о них позволяет лучше понять особенности лямбда-выражений. К тому же анонимные методы могут быть использованы в целом ряде случаев, где применение лямбда-выражений оказывается невозможным.

Синтаксис создания делегата

Шаг 1 — Объявление

modifier delegate ReturnType DelegateName ([Parameter_1]);

(модификатор delegate возвращаемый тип  Имя делегата  ([параметры]):

1. Чтобы получить делегат, сначала нужно объявить его тип. Тип делегата объявляется с помощью ключевого слова delegate. Ниже приведена общая форма объявления делегата:

delegate возвращаемый_тип имя(список_параметров);

где

  • возвращаемый_тип – обозначает тип значения, которое возвращается методами, которые будут вызваться с помощью делегата;

Делегат инициализируется путём передачи ему имени метода в качестве аргумента.

(Имя делегата  имя экземпляра делегата = new Имя делегата ( вызываемый метод )

Шаг 3 — Вызов

Вызываем созданный делегат с указанием параметров, если это необходимо.

Анонимный метод — один из способов создания безымянного блока кода, связанного с конкретным экземпляром делегата. Для создания анонимного метода достаточно указать кодовый блок после ключевого слова delegate. Покажем, как это делается, на конкретном примере: 

using System;
using System.Collections.Generic;

namespace ConsoleApplication1
{
    delegate int Sum(int number);  создания делегата

    class Program
    {
        static Sum SomeVar()
        {
            int result = 0;

            // Вызов анонимного метода
            Sum del = delegate (int number)
            {
                for (int i = 0; i <= number; i++)
                    result += i;
                return result;
            };
            return del;
        }

        static void Main()
        {
            Sum del1 = SomeVar();

            for (int i = 1; i <= 5; i++)
            {
                Console.WriteLine("Cумма {0} равна: {1}",i,del1(i));
            }

            Console.ReadLine();
        }
    }
}

Анонимные методы

Обратите внимание на получившийся результат. Локальная переменная, в область действия которой входит анонимный метод, называется внешней переменной. Такие переменные доступны для использования в анонимном методе. И в этом случае внешняя переменная считается захваченной. Захваченная переменная существует до тех пор, пока захвативший ее делегат не будет собран в "мусор". Поэтому если локальная переменная, которая обычно прекращает свое существование после выхода из кодового блока, используется в анонимном методе, то она продолжает существовать до тех пор, пока не будет уничтожен делегат, ссылающийся на этот метод.

Захват локальной переменной может привести к неожиданным результатам, как в приведенном выше примере, где локальная переменная result не обнуляется после каждого вызова анонимного метода. В результате получается необычный результат суммы чисел.

Пример формирования анонимного метода и лямбда выражения.

Создадим делегат и передадим ему функцию

using System;

namespace DAL
{
    public delegate void MyDelegate();

    class Program
    {
        public void CallerOne()  //метод
        {
            Console.WriteLine("Это первая вызываемая функция ...");
        }

        static void Main()
        {
            // Create an instance of the class
            Program p = new Program();

            // Создайте экземпляр делегата и передайте метод в качестве параметра
            MyDelegate myDelegate = new MyDelegate(p.CallerOne);
            myDelegate(); //вызов  метода
        }
    }
}

Вы можете видеть, что у меня есть делегат с именем MyDelegate, и, как вы знаете, он может содержать ссылку на метод. Итак, MyDelegate содержит ссылку на метод CallerOne() . Знайте, что вы также можете выполнить метод с помощью MyDelegate .Invoke(); вместо вызова объекта делегирования MyDelegate(); . Это определение останется аналогичным и в следующем коде. Еще один момент, на который следует обратить внимание - здесь посмотрите на возвращаемый тип и параметры. Сигнатуры делегата и метода должны быть одинаковыми для его реализации. 

using System;

namespace DAL
{
    public delegate void MyDelegate();

    class Program
    {
        public void CallerOne()
        {
            Console.WriteLine("Это первая вызываемая функция ...");
        }

        public void CallerTwo()
        {
            Console.WriteLine("Это вторая вызываемая функция ...");
        }

        static void Main()
        {
            // Create an instance of the class
            Program p = new Program();

            // Создайте экземпляр делегата и передайте метод в качестве параметра
            MyDelegate myDelegate = new MyDelegate(p.CallerOne);

            // Создайте другой экземпляр делегата и передайте другой метод в качестве параметра
            MyDelegate myDelegate1 = new MyDelegate(p.CallerTwo);

            // Invoke the delegate instances
            myDelegate();
            myDelegate1();
        }
    }
}

На приведенном выше шаге есть еще один объект делегата с именем myDelegate1, но он выполняет ту же работу, что и в первом коде. Итак, мы реализовали два объекта одного и того же делегата. 

using System;

namespace DAL
{
    public delegate void MyDelegate();

    class Program
    {
        public void CallerOne()
        {
            Console.WriteLine("This is Caller One function...");
        }

        public void CallerTwo()
        {
            Console.WriteLine("This is Caller Two function...");
        }

        public static void CallerThree()
        {
            Console.WriteLine("This is Caller Three function...");
        }

        static void Main()
        {
            // Create an instance of the class
            Program p = new Program();

            // Создайте экземпляр делегата и передайте метод в качестве параметра
            MyDelegate myDelegate = new MyDelegate(p.CallerOne);

            // Создайте другой экземпляр делегата и передайте другой метод в качестве параметра
            MyDelegate myDelegate1 = new MyDelegate(p.CallerTwo);

            // Создайте другой экземпляр делегата и передайте статический метод в качестве параметра
            MyDelegate myDelegate2 = new MyDelegate(CallerThree);

            // Вызывать экземпляры делегатов
            myDelegate();
            myDelegate1();
            myDelegate2();
        }
    }
}

Подумайте о приведенном выше коде! Почему я не должен выделять память методу во время компиляции вместо вызова функции-члена / метода с использованием class object? Итак, я пометил CallerThree как статический метод. 

using System;

namespace DAL
{
    public delegate void MyDelegate();

    class Program
    {
        public void CallerOne()
        {
            Console.WriteLine("This is Caller One function...");
        }

        public void CallerTwo()
        {
            Console.WriteLine("This is Caller Two function...");
        }

        public static void CallerThree()
        {
            Console.WriteLine("This is Caller Three function...");
        }

        static void Main()
        {
            // Create an instance of the class
            Program p = new Program();

            // Create an instance of the delegate and pass the method as a parameter. This is Single Cast
            MyDelegate myDelegate = new MyDelegate(p.CallerOne);

            // Create another instance of the delegate and pass a different method as a parameter. This is Single Cast
            MyDelegate myDelegate1 = new MyDelegate(p.CallerTwo);

            // Create another instance of the delegate and pass a static method as a parameter. This is Single Cast
            MyDelegate myDelegate2 = new MyDelegate(CallerThree);

            myDelegate();
            myDelegate1();
            myDelegate2();

            // Эта концепция называется многоадресной рассылкой
            MyDelegate MyDelegate_MultiCast_Idea = myDelegate + myDelegate1 + myDelegate2;
            MyDelegate_MultiCast_Idea();
        }
    }
}

Посмотрите на приведенный выше код. Объект MyDelegate_MultiCast_Idea является суммой всех предыдущих объектов. Это называется множественным приведением в delegates. На этом этапе вам должно быть ясно, что первый, второй и третий коды из начальной статьи будут иметь 1, 2 и 3 делегата одиночной рассылки соответственно для каждого из отдельных методов.

Теперь обратите внимание! Для реализации делегата нам необходимо определить метод, но это сложно. Если я перенесу эту идею на трехуровневую архитектуру, это означает, что изменение уровня представления должно быть отражено на бизнес-уровне и уровне данных. Короче говоря, изменения окажут влияние! Итак, подумайте о чем-нибудь, где мы могли бы написать сам метод и передать ссылку на него. Microsoft выполнила эту работу с C # 2.0, внедрив анонимные методы. 

using System;

namespace DAL
{
    public delegate void MyDelegate();

    class Program
    {
        static void Main()
        {
            // Я передал полное тело метода в экземпляре делегата 
            // У этого метода нет имени
            MyDelegate myDelegate = new MyDelegate(delegate()
            {
                Console.WriteLine("Это первая вызываемая функция ...");
            });

            MyDelegate myDelegate1 = new MyDelegate(delegate()
            {
                Console.WriteLine("Это вторая вызываемая функция ...");
            });

            MyDelegate myDelegate2 = new MyDelegate(delegate()
            {
                Console.WriteLine("Это третья вызываемая функция ...");
            });

            myDelegate();
            myDelegate1();
            myDelegate2();
        }
    }
}

Абсолютно чистый и понятный код!

Делегат содержит ссылку на метод, но здесь делегат содержит сам метод.. итак, как называется метод? Имени нет!! Вот почему он называется Анонимным методом!

Как упоминалось ранее, сигнатура делегата должна совпадать с методом, на который он ссылается, и наоборот. Есть один случай, когда анонимный метод предоставляет функциональность, отсутствующую в лямбда-выражении. Анонимные методы позволяют опустить параметр (ы). Эта функция очень важна в обоих случаях. Это может быть использовано для повышения гибкости системы с помощью анонимного метода и / или более строгой типизации с помощью лямбда-выражения. Это сравнение приведено после кода. 

using System;

namespace DAL
{
    public delegate void MyDelegate();

    class Program
    {
        static void Main()
        {
            // Здесь '=>' используется для реализации лямбда-выражения. 
            MyDelegate myDelegate = new MyDelegate(() =>
            {
                Console.WriteLine("This is Caller One function...");
            });

            myDelegate();
        }
    }
}

Давайте проведем сравнение на анонимный метод и Лямбда-Выражения. Этот пример поможет, по крайней мере, две идеи. Первый - это работа с параметризованными делегатами, а второй - сравнение анонимного метода и лямбда-выражения. 

using System;

namespace DAL
{
    public delegate void MyDelegate(int num);

    class Program
    {
        static void Main()
        {
            MyDelegate myDelegate = new MyDelegate(delegate (int num)
            {
                Console.WriteLine("This is Caller One function...");
            });

            myDelegate(211);
        }
    }
}

Вы можете принять к сведению, что вы передали параметру num значение 211, но Анонимный метод может опустить его, и программа будет выполнена. Теперь, с тем же делегатом, посмотрите на приведенный ниже код, который использует лямбда-выражение. Это выдаст ошибку во время компиляции, потому что вам нужно будет передать параметр в теле метода для компиляции и выполнения. Как передать параметр в этом? Я оставляю эту очень простую работу на ваше усмотрение, и вы должны опубликовать свой ответ в комментариях. 

using System;

namespace DAL
{
    public delegate void MyDelegate(int num);

    class Program
    {
        static void Main()
        {
            MyDelegate myDelegate = new MyDelegate(delegate(int num)
            {
                Console.WriteLine("This is Caller One function...");
            });

            myDelegate(211);
        }
    }
}
