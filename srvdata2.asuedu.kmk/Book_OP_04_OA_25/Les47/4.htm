Тема 4. Описание членов класса.
    Назад

Предположим, что есть некоторый объект, характеризующийся определенными параметрами, например, сотрудник фирмы. У него есть фамилия, имя, отчество, возраст и т. п. В таких случаях удобно каждого сотрудника описывать не рядом независимых переменных (строкового типа для фамилии, имени и отчества, целого типа для возраста), а одной переменной, например, типа Human, внутри которой и содержаться переменные для фамилии, имени, отчества и возраста. Этот факт здесь самый важный, что в переменной типа Human содержатся другие переменные. Типа Human нет среди встроенных типов данных, но его можно ввести. Для этого следует создать соответствующий класс Human.

Рассмотрим основные правила и примеры построения и использования классов.

Для создания класса нужно выбрать пункт меню Проект -> Добавить класс.

В открывшемся окне выбрать элемент Класс и ввести имя класса, например, Human. По умолчанию будут использоваться имена Class1 и т.д. После этого нажать кнопку Добавить. В результате получим шаблон вида

using System;

using System.Collections.Generic;

using System.Linq;

using System.Text;

using System.Threading.Tasks;

namespace Project1

 {

class Human { }

}

Здесь Project1 – имя пространства имен, в которое войдет наш класс Human.

Теперь надо во внутренних скобках записать код. Этот код обычно включает в себя следующие фрагменты:

  • • описание полей;
  • • описание свойств;
  • • описание методов.

Описанные здесь поля, свойства и методы называются членами класса. Могут быть и другие члены класса.

Поле класса (переменная-член) — переменная, связанная с классом или объектом. Все данные объекта хранятся в его полях. Доступ к полям осуществляется по их имени. Обычно тип данных каждого поля задаётся в описании класса, членом которого является поле.

Как правило, поля объявляются закрытыми, т.е. используется модификатор доступа private.

При необходимости значение поля можно инициализировать непосредственно в теле класса.

Свойства объекта – это средства доступа к полям, позволяющие изменять его данные и выполнять его код.

Чтобы использовать свойства для изменения значений полей и их чтения, нужно описать, соответственно, функции set и get.

Эти функции должны быть открытыми, т.е. иметь модификатора доступа public.

Функция set присваивает значение value некоторому полю. При этом может, например, выполняться проверка допустимости вводимого значения. Функция get возвращает некоторый результат, который получается на основе значений полей, а может быть просто значением некоторого поля.

Этот вариант чаще всего и используется.

 Если поля объявить открытыми, т.е. использовать модификатор доступа public, то можно будет читать и изменять их значения непосредственно присваиванием из методов других классов.

В этом случае необходимость описания свойств отпадает. Но это нецелесообразно. Так как именно свойства позволяют регулировать чтение или изменение поля, проверять допустимость новых значения полей и т.п. Необязательно должны присутствовать обе функции и set, и get. Например, свойство может быть только для чтения, тогда описывается только функция get. Методы представляют собой процедуры и функции, принадлежащие заданному объекту. Можно сказать, что методы определяют поведение объекта. Поэтому они, как правило, являются открытыми.

Можно использовать методы для чтения или изменения значений полей, вместо свойств. В этом случае придется описать одну функцию для чтения и другую – для изменения. Поэтому проще использовать именно свойства.

Рассмотрим пример создания класса Human. В качестве полей будем использовать фамилию, имя, отчество и возраст сотрудника. Для их хранения будем использовать поля lastname, name, secondname, age. Для работы с этими полями создадим свойства LastName, Name, SecondName, Age. Первые три будем использовать только для ввода, а последнее - и для ввода, и для чтения. Кроме того, опишем свойство FullName, которое будет выводить полное имя сотрудника. Создадим метод Info(), суть которого будет заключаться в выводе на консоль данных о сотруднике.
